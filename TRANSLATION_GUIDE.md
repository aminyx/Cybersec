# Руководство по переводу

Как переводить курс на новый язык, сохраняя единый стиль. Эталон — таджикская версия (`tg/`), выполненная полностью по этим правилам.

---

## 1. Прежде чем начать

- Заяви язык через Issue (`[lang] Перевод на <язык>`), чтобы не дублировать работу.
- Добавь себя в [MAINTAINERS.md](MAINTAINERS.md) как ответственного за язык.
- Код языка — по ISO 639-1: `uz`, `ky`, `kk`, `en` и т.д. Папка называется этим кодом.

## 2. Структура папки языка

Скопируй полный набор из `ru/` (или `tg/` как образец):

```
<lang>/
  README.md, roadmap.md, faq.md, study-guide.md, student-pack.md, home-lab.md,
  month-01..09-*.md, exams.md, checklists.md, projects.md, interview-questions.md,
  after-course.md, certificate.md, advanced-course.md,
  glossary.md, resources.md, progress.md, _translation-status.md
```

Ничего не удаляй из структуры — только переводи.

## 3. Золотые правила

1. **Технические термины оставляй на английском** + пояснение на языке.
   Не выдумывай перевод для `prompt injection`, `reverse shell`, `SQL injection` и т.п.
   Смотри, как это сделано в `tg/glossary.md`.
2. **Сохраняй формат дня** дословно: блоки 📺 / 💻 / ✍️ / 🎯 в том же порядке.
   От этого зависит парсер сайта — сломаешь формат, сломаешь `build-data.py`.
3. **Сохраняй все ссылки и якоря.** URL внешних ресурсов не меняются.
4. **Тон** — на «ты», дружелюбный, честный, мотивирующий. Не канцелярит.
5. **Числа, дни, названия месяцев** — как в оригинале (день 1–270 сквозной).

## 4. Внутренние ссылки

- Ссылки внутри `<lang>/` ведут на файлы **своего** языка.
- Пока файл не переведён — временно ссылайся на `../ru/<file>` и отметь это в `_translation-status.md`.
- Когда перевёл файл — переведи и ссылки на него по всей папке.

**Массовая правка ссылок (кириллица):** используй Perl с `use utf8;` и запуск `perl -CSD`, иначе байтовые паттерны не совпадут с UTF-8. Для Python-скриптов вывода — `sys.stdout.reconfigure(encoding="utf-8")` (иначе падает на Windows-консоли cp1251).

## 5. Порядок перевода (рекомендованный)

1. Входной набор: `README`, `faq`, `study-guide`, `roadmap`, `student-pack`, `home-lab`.
2. `month-01` … `month-09` по порядку.
3. Оценивание: `exams`, `checklists`, `projects`.
4. Карьера/справка: `after-course`, `certificate`, `advanced-course`, `glossary`, `resources`, `progress`, `interview-questions`.

Веди `_translation-status.md` (таблица «файл → статус»), чтобы прогресс был виден.

## 6. Качество

- **Не заливай машинный перевод целиком без вычитки** — качество падает. Переводи по файлу и вычитывай.
- Проверяй, что технические инструкции остались точными (команды, флаги, пути — не переводятся).
- После завершения языка обнови корневой [README.md](README.md) — добавь язык в переключатель, и пересобери сайт: `python site/build-data.py` (парсер подхватит новый язык из папки).

## 7. Локальные юридические ссылки

В юридических предупреждениях адаптируй ссылку на закон под юрисдикцию языка (например, для узбекского — соответствующие статьи УК РУз), сохраняя суть: атака чужих систем без разрешения — преступление.

## 8. Проверка перед сдачей

- [ ] Все файлы структуры на месте
- [ ] Формат дня (📺/💻/✍️/🎯) сохранён везде
- [ ] Внутренние ссылки ведут на свой язык (или помечены в `_translation-status.md`)
- [ ] Технические термины и команды не искажены
- [ ] `python site/build-data.py` отрабатывает и показывает новый язык
- [ ] Обновлён корневой README и `_translation-status.md`

Спасибо, что делаешь курс доступнее ещё для одного языка. 🌍
