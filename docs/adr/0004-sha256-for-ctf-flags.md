# ADR-0004: Флаги CTF хранятся как SHA-256

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Нужны CTF-задания с проверкой флага. Репозиторий публичный — если хранить флаг открытым текстом, любой подсмотрит ответ в исходниках. При этом хочется:
- проверку без сервера (офлайн);
- невозможность подсмотреть ответ;
- простоту добавления заданий.

Варианты: (а) сервер проверки флагов (как на CTF-платформах); (б) флаги открытым текстом в репо; (в) хранить только хэш флага и сравнивать хэши.

## Решение

В `challenges/challenges.json` хранится **только `SHA-256` флага**, не сам флаг. `challenges/check.py` хеширует введённый пользователем флаг и сравнивает с сохранённым хэшем.

## Последствия

**Плюсы:**
- Ответ нельзя подсмотреть в репозитории (SHA-256 практически необратим для флагов достаточной энтропии).
- Проверка полностью **офлайн**, без сервера и интернета.
- Добавить задание просто: посчитать `sha256` флага и вписать хэш.
- CI проверяет, что хэши валидны (`[0-9a-f]{64}`).

**Минусы / компромиссы:**
- Слабые/угадываемые флаги можно перебрать по словарю (как и любой хэш) — поэтому флаги делаем неочевидными.
- Нет серверной статистики решений и защиты от «передачи флага» между студентами (для учебного, не соревновательного контекста это приемлемо).
- Нет rate-limiting на попытки (не нужен офлайн).

**Что это закрывает на будущее:**
- Для соревновательного режима с leaderboard понадобится сервер (отдельный модуль, см. [ROADMAP.md](../../ROADMAP.md)); базовый офлайн-режим остаётся как есть.
- Подход совпадает с тем, чему учит курс (хэши необратимы, соль, стойкость) — задания заодно иллюстрируют принцип.
