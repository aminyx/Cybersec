# ADR-0003: Прогресс в localStorage, без бэкенда

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Студенту нужно отмечать пройденные дни, экзамены, проекты и видеть прогресс/ранги. Где хранить состояние?

Варианты: (а) бэкенд с аккаунтами и БД; (б) сторонний BaaS (Firebase и т.п.); (в) браузерный `localStorage` без сервера.

Силы: бесплатность, приватность, отсутствие обслуживания, работа офлайн, простота.

## Решение

Прогресс хранится **только в браузере студента** через `localStorage` (ключи `csc.lang`, `csc.days`, `csc.exams`, `csc.projects`). Сервера, аккаунтов и сбора данных нет.

## Последствия

**Плюсы:**
- Нулевая инфраструктура и стоимость; нечего взламывать и утекать.
- Максимальная приватность: данные не покидают устройство.
- Работает офлайн, мгновенно.

**Минусы / компромиссы:**
- Прогресс не синхронизируется между устройствами и браузерами.
- Сбрасывается при очистке данных сайта / инкогнито / смене домена-порта.
- Нельзя сделать серверный leaderboard или аналитику группы на этих данных.

**Митигация:**
- Дублирующий «офлайновый» трекер прогресса есть и в Markdown (`progress.md`).
- Нумерация дней стабильна между версиями (кроме MAJOR), чтобы прогресс переживал обновления курса ([VERSIONING.md](../../VERSIONING.md)).

**Что это закрывает на будущее:**
- Синхронизация между устройствами, leaderboard, аналитика для преподавателей — это **опциональные модули с бэкендом** (см. [ROADMAP.md](../../ROADMAP.md)), которые не меняют поведение ядра по умолчанию (офлайн, приватно).
