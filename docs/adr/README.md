# Architecture Decision Records (ADR)

Здесь фиксируются **ключевые архитектурные решения** проекта: не только *что* решено, но и *почему*. Через год-два это спасает сопровождающего от вопроса «почему тут так странно сделано?».

## Что такое ADR

Короткий документ на одно решение: контекст (какую проблему решали), само решение, последствия (плюсы, минусы, компромиссы). Однажды принятое решение не удаляется — если передумали, заводится новый ADR со статусом «заменяет ADR-XXXX».

## Формат

Каждый ADR — по [шаблону](0000-template.md): Статус · Контекст · Решение · Последствия.

## Как добавить ADR

1. Скопируй [0000-template.md](0000-template.md) → `000N-краткое-название.md`.
2. Заполни разделы, поставь статус `Предложено`.
3. Обсуди в PR; после мёржа статус → `Принято`.
4. Добавь строку в таблицу выше.

Подробнее об архитектуре в целом — [ARCHITECTURE.md](../../ARCHITECTURE.md).
