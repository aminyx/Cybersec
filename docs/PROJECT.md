## 1. Что это за проект

**CyberSec Course** — бесплатный двуязычный (русский + таджикский) курс кибербезопасности «с нуля до Junior», обёрнутый в полноценную образовательную платформу.

Это не «список ссылок» и не набор PDF. Это:
- **Структурированная программа на 270 дней** (9 месяцев), где каждый день расписан как урок: теория → практика → задание → самопроверка.
- **Инфраструктура вокруг курса**: интерактивный сайт с трекингом прогресса, CTF-задания с автопроверкой, шаблоны профессиональных документов, банк вопросов для собеседований, CI для проверки студенческих проектов, генератор сертификата, гайды для сообщества.

**Цель проекта:** довести человека без опыта до состояния, в котором его **нанимают** на позицию джуна (SOC-аналитик, стажёр-пентестер, AppSec), и дать всё необходимое бесплатно и легально.

**Ключевая идея:** нанимают не за просмотренные видео, а за **портфолио** (write-up'ы, проекты, отчёты) и умение думать. Поэтому весь курс завязан на практику и публикацию результатов на GitHub.

## 2. Философия и принципы

Проект построен на нескольких жёстких принципах — они объясняют большинство решений:

1. **Практика важнее теории.** Каждый день содержит задание руками. Без задания день не засчитывается.
2. **Фундамент нельзя пропускать.** Месяцы 1–6 (сети, Linux, веб, пентест, защита) — это то, что делает нанимаемым. Современный стек (облако, AI) — надстройка сверху, а не замена.
3. **Всё бесплатно и легально.** Только официальные платформы (TryHackMe, PortSwigger, Codeby Games, flaws.cloud…), только свои машины и учебные полигоны.
4. **Против выгорания.** Отдельный гайд по технике обучения, резервные дни, правило «никогда не пропускай два дня подряд», система достижений — всё чтобы человек дошёл до конца.
5. **Честность.** Проект не обещает «профи за полгода». Он обещает «нанимаемый джун за 6–9 месяцев при 4–5 ч/день», и прямо говорит, где что не работает (например, сертификат самообучения ≠ аккредитованный).
6. **Портфолио как результат.** Write-up'ы, проекты, отчёты по шаблонам — конечный продукт каждого этапа.
7. **Без зависимости от инфраструктуры.** Сайт — статический, без сборки и бэкенда. CTF-проверка — офлайн. Всё работает локально и хостится бесплатно.

## 3. Для кого

**Прямая аудитория — студент:** человек без опыта в ИБ (но, как правило, с базовым Linux/Python), который хочет войти в профессию самостоятельно.

**Языковая аудитория:**
- 🇷🇺 русскоязычные (Россия, Казахстан, Кыргызстан, Узбекистан — русский как рабочий язык ИБ);
- 🇹🇯 таджикоязычные (Таджикистан) — для них это, по сути, первый полный курс по ИБ на родном языке.

**Вторичная аудитория — преподаватель/контрибьютор:** тот, кто хочет вести по курсу группу, перевести его на новый язык, добавить лаборатории или записать видео. Для них — [CONTRIBUTING.md](../CONTRIBUTING.md), [community-setup.md](community-setup.md), [github-org.md](github-org.md), [video-scripts.md](video-scripts.md).

## 5. Как устроен курс

### Две фазы

| Фаза | Месяцы | Дни | Что даёт |
|---|---|---|---|
| **Фаза 1 — Фундамент** | 1–6 | 1–180 | Делает **нанимаемым**. Сети/Linux → лаборатория/privesc → веб → пентест/AD → SOC/форензика → карьера |
| **Фаза 2 — Современный стек** | 7–9 | 181–270 | Делает **конкурентоспособным**. Cloud/K8s → DevSecOps/Detection/EDR → AI/LLM Security + MCP |

### Формат месяца

Каждый файл `month-XX-*.md` устроен одинаково:
- Заголовок `# Месяц N — Тема`
- `**Цель месяца:**` — что человек сможет в конце
- Список главных ресурсов месяца
- 4 недели (`## Неделя N — …`)
- Дни (`### День N — …`), пронумерованные **сквозно** (Месяц 2 начинается с «День 31», Месяц 9 заканчивается «День 270»)
- «Итог месяца» — чек-лист навыков и ссылка на следующий месяц

### Формат дня

Каждый день — это микро-урок из 4 блоков:

| Блок | Маркер | Что это |
|---|---|---|
| Теория | 📺 / 📖 | Видео или чтение по ссылке (~1,5 ч) |
| Практика | 💻 | Руками, реальные задачи (~2 ч) |
| Задание | ✍️ | Сделать самому и записать (~30 мин) |
| Проверь себя | 🎯 | Вопрос без гугла (~15 мин) |

Эта строгая структура — не только для читателя. **Сайт парсит её автоматически** (см. [раздел 7](#7-компонент-сайт-курса)): по этим маркерам `build-data.py` вытаскивает содержимое каждого блока. Поэтому формат нельзя ломать — иначе сайт не соберёт данные.

### Оценивание

- **6 экзаменов** ([exams.md](../ru/exams.md)) — практические, «как в реальных компаниях», привязаны к месяцам.
- **10 проектов** ([projects.md](../ru/projects.md)) — Python-инструменты для портфолио.
- **Чек-листы навыков** ([checklists.md](../ru/checklists.md)) — «умею», а не «прошёл».

## 6. Двуязычность (RU/TJ)

### Как это устроено

Полностью параллельные папки `ru/` и `tg/` с одинаковым набором файлов. Корневой `README.md` — лендинг с выбором языка.

**Принципы перевода (зафиксированы в [CONTRIBUTING.md](../CONTRIBUTING.md)):**
1. Технические термины остаются на английском + пояснение на языке (нет смысла выдумывать таджикский перевод для «prompt injection»).
2. Внутренние ссылки в `tg/` ведут на таджикские файлы-сиблинги; единственная ссылка на `ru/` — на русский индекс (для тех, кому нужно сравнить).
3. Структура не меняется, только переводится содержание.

### Статус

Обе версии **полные**. Таджикская — 100% (все 9 месяцев + все вспомогательные файлы). Детали — в [tg/_translation-status.md](../tg/_translation-status.md).

### Техническая заметка

Массовые правки таджикских ссылок делались perl-скриптом. Важный нюанс: для работы с кириллицей в perl нужен `use utf8;` в скрипте + запуск `perl -CSD` (иначе байтовые паттерны не совпадают с UTF-8 входом). Аналогично — Python-скрипты с кириллицей в выводе падают на Windows-консоли (cp1251); решение — `sys.stdout.reconfigure(encoding="utf-8")` в начале скрипта.

## 7. Компонент: сайт курса

### Что это

Интерактивная витрина и рабочий инструмент прохождения курса: карта, карточки месяцев, все 270 дней с содержанием, поиск, трекинг прогресса, достижения. Двуязычный, тёмная терминальная тема.

### Архитектура

**Осознанно без фреймворков, без сборки, без бэкенда.** Причины: работает где угодно, хостится бесплатно на GitHub Pages, не устаревает, студент может открыть локально одной командой.

```
month-*.md (RU + TJ)          ← источник правды (сам курс)
      │
      ▼  python site/build-data.py   (парсит markdown)
   data.js                    ← window.COURSE_DATA = {ru:[...], tg:[...]}
      │
      ▼  загружается в
index.html + styles.css + app.js  ← рендерит интерфейс в браузере
```

### Файлы

| Файл | Роль |
|---|---|
| `index.html` | Разметка: шапка, hero с «терминалом прогресса», секции roadmap/месяцы/достижения, дровер дня, поиск |
| `styles.css` | Стили. CSS-переменные, тёмная тема, отзывчивость (375/640/1024/1440px) |
| `app.js` | Вся логика (ниже) |
| `data.js` | **Автоген.** Данные курса на двух языках. Не редактировать |
| `build-data.py` | Парсер markdown → data.js |

### Что умеет app.js

- **i18n** — весь интерфейс и контент переключаются RU↔TJ (объект `I18N` + данные из `data.js`). Выбор языка хранится в `localStorage`.
- **Поиск** — по клавише `/` или `Ctrl/Cmd+K`. Ищет по названиям дней и содержанию всех блоков, ранжирует (совпадение в заголовке выше), навигация стрелками + Enter.
- **Прогресс** — отметка пройденных дней, кольцо прогресса, полоса в шапке. Хранится в `localStorage` (`csc.days`).
- **Достижения** — ранги Bronze/Silver/Gold/Diamond, чек-листы 6 экзаменов и 10 проектов (`csc.exams`, `csc.projects`).
- **Карточка дня (дровер)** — теория/практика/задание/проверка, кнопка «отметить пройденным», навигация `←`/`→` между днями.

### Дизайн

Подобран по дизайн-системе `ui-ux-pro-max` под профиль «security/terminal»:
- Шрифты: **JetBrains Mono** (заголовки, данные) + **IBM Plex Sans** (текст) — обе с полной кириллицей (критично для RU+TJ).
- Палитра: глубокий тёмный (`#050A14`) + терминальный зелёный (`#34D399`) + золото/серебро/бронза/бриллиант для рангов.
- Контраст текста 7.7–18:1 (WCAG AAA), все тач-таргеты ≥44px, поддержка `prefers-reduced-motion`, нет горизонтальной прокрутки на мобильном.

### Как обновлять

После **любой** правки учебных `month-*.md`:
```bash
python site/build-data.py
```
Это пересоберёт `data.js`. Сайт не хранит копию курса — он всегда читает актуальные данные.

Подробности — [site/README.md](../site/README.md).

## 8. Компонент: CTF-челленджи

### Что это

Небольшие задания на 10–20 минут с **автоматической проверкой флага** — офлайн, без сервера и интернета.

### Как устроена автопроверка (безопасно)

Ключевое решение: **сами флаги в репозитории не хранятся — только их SHA-256.**

```
challenges.json         ← задание + подсказки + flag_sha256 (НЕ сам флаг)
      │
check.py <id> <флаг>    ← считает sha256(введённый флаг) и сравнивает с сохранённым
```

Подсмотреть ответ в файлах нельзя (хэш необратим), но проверить свой — можно мгновенно и офлайн. Формат флага: `CSC{...}`.

### Что внутри

5 стартовых заданий (Base64, ROT13, идентификация хэша, поиск брутфорса в `auth.log`, поиск сканера в `access.log`) + артефакты-логи. Каждое привязано к дню курса, когда его уже можно решить. Все 5 проверены на решаемость (расшифровка → совпадение с хэшем).

### Использование

```bash
python challenges/check.py                       # список + прогресс
python challenges/check.py w01-base64            # задание + подсказки
python challenges/check.py w01-base64 "CSC{...}" # проверить флаг
python challenges/check.py --score               # сколько решено
```

Прогресс решённых хранится в `challenges/.solved` (в `.gitignore`, у каждого свой).

### Как добавить задание

## 16. Технические детали и требования

### Зависимости

| Что | Зачем | Обязательно? |
|---|---|---|
| Python 3.8+ | `build-data.py`, `check.py`, генератор сертификата | Да, для сайта/CTF |
| `fpdf2` (`pip install fpdf2`) | Генератор сертификата | Только для сертификата |
| Любой статический сервер | Запуск сайта локально (`python -m http.server`) | Да, для сайта |
| Браузер | Сайт | Да |

Сайт **не требует** Node.js, npm, сборщиков, интернета (шрифты — с Google Fonts, при офлайне подхватится системный моноширинный/санс-фолбэк).

### Хранение состояния

Прогресс студента живёт **только в его браузере** (`localStorage`, ключи `csc.lang`, `csc.days`, `csc.exams`, `csc.projects`) и в файле `challenges/.solved`. Аккаунтов, сервера, сбора данных — нет.

### Совместимость (Windows)

Проект разрабатывался на Windows. Учтено:
- Python-скрипты форсируют UTF-8 вывод (иначе cp1251-консоль падает на кириллице).
- Пути и команды кроссплатформенны.

## 17. Развёртывание

### Локально

```bash
python -m http.server 8129 --directory site
```

### GitHub Pages (бесплатно, публично)

1. Залить репозиторий на GitHub.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Сайт: `https://<username>.github.io/<repo>/site/`.

Чтобы сайт открывался в корне домена — перенести содержимое `site/` в корень (и поправить путь `OUT` в `build-data.py`) или настроить Actions, публикующий только `site/`.

### CI

`.github/workflows/project-check.yml` предназначен для **проектов студентов**, а не для самого репозитория курса. Студент копирует его в свой проект.

## 21. FAQ по проекту

**Почему сайт без React/фреймворка?**
Чтобы работал где угодно без сборки, хостился бесплатно на Pages и не устаревал. Для дашборда над статичными данными фреймворк — лишняя сложность.

**Почему данные сайта генерируются, а не пишутся руками?**
Чтобы был **один источник правды** — сам курс (`month-*.md`). Иначе сайт и тексты разъезжались бы. Правишь курс → `build-data.py` → сайт актуален.

**Почему флаги CTF хранятся как хэши?**
Чтобы нельзя было подсмотреть ответ в репозитории, но можно было проверить свой офлайн. Стандартный приём для offline-CTF.

**Почему часть вещей (Discord, орг, видео) — «только гайды»?**
Их нельзя создать за пользователя: нужен его аккаунт и, для видео, запись. Поэтому отдано максимально готовым к применению — вставить тексты и нажать кнопки.

**Можно ли использовать проект коммерчески / для своей группы?**
Да — он открытый. См. [CONTRIBUTING.md](../CONTRIBUTING.md). Главное — сохранять принципы (бесплатно, легально, честно).

**Как поддерживать актуальность?**
Раз в год проверять ссылки, версии инструментов, новые темы Фазы 2 (см. раздел «Поддержка версий» в CONTRIBUTING).
