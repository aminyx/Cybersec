# Практические экзамены (как в реальных компаниях)

6 экзаменов, имитирующих реальные технические собеседования и тестовые задания. Сдавай **сам, без подсказок**, с таймером. Каждый заканчивается **отчётом** — именно отчёты показывают работодателю, что ты умеешь думать, а не только тыкать инструменты.

**Правила:**
- Только легальные цели (свои ВМ, учебные платформы).
- Таймер включён — реальные задания ограничены по времени.
- Результат — не «получил root», а **отчёт**: что нашёл, как, чем это опасно, как чинить.
- Не сдал — не страшно. Разбери, где застрял, подтяни, пересдай через неделю.

---

## 📝 Экзамен 1 — Linux (после месяца 2)

**Сценарий:** дана Linux-машина. Ты — пентестер, задача — получить root и отчитаться.

**Задачи:**
1. Провести разведку (nmap, перечисление сервисов).
2. Получить первичный доступ (foothold).
3. Повысить привилегии до root.
4. Найти «флаги» (user.txt, root.txt).

**Отчёт должен содержать:**
- Методология (шаги по порядку)
- Найденные уязвимости
- Как повысил привилегии
- Скриншоты-доказательства
- Рекомендации по защите

**Где брать цель:** новая THM/VulnHub машина Easy, которую не видел.
**Время:** 3 часа.
**Проходной балл:** root + внятный отчёт.

## 📝 Экзамен 2 — Web (после месяца 3)

**Сценарий:** веб-приложение на тестирование. Найди уязвимости, докажи, предложи фиксы.

**Задачи:**
1. Найти **SQLi** — извлечь данные из БД.
2. Найти **XSS** — reflected или stored.
3. Найти **IDOR** — доступ к чужим данным.
4. Найти **SSRF** (если есть).
5. Для каждой — PoC и рекомендация по исправлению.

**Отчёт должен содержать:**
- Каждая уязвимость: описание, шаги воспроизведения, PoC, CVSS, как чинить
- Приоритизация по критичности

**Где брать цель:** [OWASP Juice Shop](https://github.com/juice-shop/juice-shop), DVWA на High, или незнакомая веб-машина THM.
**Время:** 4 часа.
**Проходной балл:** минимум 3 уязвимости с PoC и рекомендациями.

## 📝 Экзамен 3 — Blue Team / Incident Response (после месяца 5 и 8)

**Сценарий:** произошёл инцидент. Даны артефакты. Расследуй и напиши Incident Report.

**Дано:** `pcap` (трафик) + `evtx` (Windows-логи) + `auth.log` + `syslog`.

**Задачи:**
1. Определить, что произошло (тип атаки).
2. Найти **IOC** (IP, хэши, домены, файлы).
3. Разложить атаку по **MITRE ATT&CK**.
4. Наложить на **Cyber Kill Chain**.
5. (уровень месяца 8) Предложить **правила детекта** (Sigma) на будущее.

**Отчёт (Incident Report) должен содержать:**
- Timeline (хронология атаки)
- Список IOC
- MITRE ATT&CK mapping
- Оценка ущерба / что скомпрометировано
- Рекомендации + детекты

**Где брать:** [CyberDefenders](https://cyberdefenders.org/), [malware-traffic-analysis.net](https://www.malware-traffic-analysis.net/), LetsDefend.
**Время:** 4 часа.
**Проходной балл:** верно определён инцидент + IOC + ATT&CK + отчёт.

## 📝 Экзамен 4 — Cloud / AWS (после месяца 7)

**Сценарий:** дан AWS-аккаунт (учебный). Проведи аудит безопасности.

**Задачи:**
1. Найти **открытый S3-бакет** и что в нём.
2. Найти **неправильный IAM** (лишние/опасные права).
3. Найти путь **повышения привилегий** в IAM.
4. Проверить, как обнаружить эти действия (CloudTrail).

**Отчёт должен содержать:**
- Каждый мисконфиг: риск, доказательство, как исправить
- IAM privesc-цепочка
- Рекомендации по мониторингу (CloudTrail/GuardDuty)

**Где брать:** [flaws.cloud](http://flaws.cloud/), [flaws2.cloud](http://flaws2.cloud/), [CloudGoat](https://github.com/RhinoSecurityLabs/cloudgoat).
**Время:** 4 часа.
**Проходной балл:** найдены S3 + IAM-проблемы + privesc + отчёт.

## 📝 Экзамен 5 — Kubernetes (после месяца 7)

**Сценарий:** дан доступ к namespace в кластере. Захвати кластер и отчитайся.

**Задачи:**
1. Разведка кластера из pod'а.
2. Извлечь **Secret**.
3. Найти **RBAC**-мисконфиг → повышение привилегий.
4. Выполнить **container/pod escape** на node.
5. Добраться до контроля над кластером.

**Отчёт должен содержать:**
- Цепочка «pod → namespace → cluster»
- Каждый шаг с доказательством
- Рекомендации (RBAC, Pod Security, Network Policy, Falco)

**Где брать:** [Kubernetes Goat](https://madhuakula.com/kubernetes-goat/).
**Время:** 4 часа.
**Проходной балл:** escape + захват + отчёт с рекомендациями.

## 📝 Экзамен 6 — AI / LLM Security (после месяца 9)

**Сценарий:** дан чат-бот с доступом к инструментам (MCP/tool calling). Протестируй его безопасность.

**Задачи:**
1. Обойти защиту промпта (**prompt injection**).
2. Найти **prompt leak** (извлечь system prompt).
3. Найти **tool injection** (заставить агента злоупотребить инструментом).
4. Проверить **insecure output handling** (XSS/инъекция через вывод).
5. Предложить фиксы (guardrails, permission model, валидация).

**Отчёт должен содержать:**
- Каждая находка: приём, PoC, риск (OWASP LLM / MITRE ATLAS), фикс
- Рекомендации по защите AI-агента

**Где брать:** [Gandalf](https://gandalf.lakera.ai/), [PortSwigger LLM labs](https://portswigger.net/web-security/llm-attacks), свой уязвимый MCP-сервер из месяца 9.
**Время:** 4 часа.
**Проходной балл:** prompt injection + leak + tool injection + отчёт с фиксами.

## 🎯 Как использовать экзамены

- Сдавай **после** соответствующего месяца (указано в скобках).
- Все отчёты складывай в отдельный репозиторий GitHub `security-exams` — это прямое доказательство навыка для работодателя.
- Отчёт важнее «взлома»: 80% ценности — в том, как ты объясняешь находку и её исправление.
- Провалил — это диагностика, а не приговор. Запиши слабое место, подтяни, пересдай.

> На реальных собеседованиях в ИБ часто дают именно такие задания. Пройдя эти 6 — ты приходишь на собес подготовленным, а не впервые.
