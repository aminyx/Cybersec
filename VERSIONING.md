# Версионирование курса

Курс — живой продукт: инструменты, облачные сервисы и угрозы меняются каждый год. Чтобы студент понимал, какую редакцию он проходит, введена система версий.

Текущая версия — в файле [VERSION](VERSION). История — в [CHANGELOG.md](CHANGELOG.md).

---

## Схема версий: `MAJOR.MINOR.PATCH`

| Часть | Когда растёт | Пример |
|---|---|---|
| **MAJOR** | Обновление под стек нового года («редакция 2028»): переработка Фазы 2, новые обязательные темы, устаревшее удалено | `1.x.x → 2.0.0` |
| **MINOR** | Новые лаборатории, модули, язык перевода, крупный раздел — без слома существующего | `1.0.x → 1.1.0` |
| **PATCH** | Исправления: битые ссылки, опечатки, обновление версий инструментов, мелкие уточнения | `1.0.0 → 1.0.1` |

Это соответствует схеме, которую удобно показывать пользователям:

```
CyberSec Course
├── Редакция 2026
│   ├── v1.0.0 — Первый официальный релиз
│   ├── v1.1.0 — Новые лаборатории / язык
│   └── v1.0.1 — Исправления ссылок
└── Редакция 2028
    └── v2.0.0 — Обновление под стек 2028
```

## «Редакция года»

В дополнение к номеру версии у курса есть **редакция** — год, под инструменты и практики которого он актуализирован (сейчас: **2026**). Редакция обновляется вместе с MAJOR-версией. Указывай её в README и на сайте, чтобы студент видел свежесть материала.

---

## Ритм релизов (рекомендация)

- **Ежегодно** (например, к началу учебного года) — ревизия актуальности: живы ли ссылки, не устарели ли инструменты и облачные сервисы, не появились ли новые важные темы. Итог — MINOR или MAJOR.
- **По мере надобности** — PATCH-фиксы, не дожидаясь года.

## Как выпустить версию

1. Внеси изменения, обнови [CHANGELOG.md](CHANGELOG.md) (перенеси из `[Unreleased]`).
2. Обнови файл [VERSION](VERSION).
3. Пересобери артефакты: `python site/build-data.py` и `python scripts/build_stats.py`.
4. Пройди [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).
5. Создай git-тег и GitHub Release:
   ```bash
   git tag -a v1.1.0 -m "CyberSec Course v1.1.0"
   git push origin v1.1.0
   ```
6. Опиши релиз на GitHub, приложи ключевые изменения из CHANGELOG.

## Совместимость и прогресс студента

Прогресс хранится в браузере студента по номерам дней (1–270). Нумерация дней **стабильна между PATCH и MINOR** — прогресс не теряется. При MAJOR (переработка структуры) возможен сдвиг; предупреждай об этом в CHANGELOG и, по возможности, сохраняй нумерацию Фазы 1.

## Для тех, кто ведёт группу

Фиксируй, по какой версии идёт твоя группа (например, `v1.0.0`), чтобы ссылки и задания совпадали. Обновляйся между потоками, а не посреди курса.
